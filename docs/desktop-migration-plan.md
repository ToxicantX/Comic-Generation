# 漫画流水线桌面版迁移计划

状态：执行中
目标平台：Windows 10/11，桌面窗口尺寸基线为 1180x720 及以上
当前入口：`http://127.0.0.1:8199`

## 1. 目标与非目标

桌面版的目标不是给网页增加一个窗口边框，而是形成一个可以安装、启动、诊断、升级和恢复的漫画生产工作台。现有已验证的小说处理、设定、素材、章节、审核、任务和图片生成能力继续作为业务核心。

首个正式桌面版本必须满足：

- 单实例启动，后台启动过程可见，失败时给出可操作的诊断。
- 围绕小说项目组织工作区，全局功能与小说内功能不重复。
- 配置、密钥、PostgreSQL 数据、小说原文和生成结果在升级后仍保留。
- 原生文件选择、打开目录、任务通知和外部链接通过受限桥接实现。
- 浏览器模式在迁移期间保持可用，不能一次性切断现有工作流。
- Windows 安装、覆盖升级、异常退出、重启恢复和卸载保留数据经过实机验收。

本阶段不做：

- 不重写已经稳定的 Python 漫画业务脚本。
- 不把 PostgreSQL 降级为 SQLite；小说、章节、审核和任务仍以 PostgreSQL 为事实来源。
- 不强制安装 ComfyUI。直连图片 API 是默认路径，本地模型仍是可选后端。
- 不在第一阶段迁移或删除现有 Docker 数据卷。

## 2. 当前架构基线

```text
浏览器
  -> console/static/index.html + app.js + CSS
  -> console/server.py (ThreadingHTTPServer, 8199)
  -> console/db.py
  -> PostgreSQL
  -> scripts/*.py / PowerShell 流水线
  -> 直连图片 API 或可选 ComfyUI
```

可保留模块：

| 模块 | 处理方式 | 原因 |
| --- | --- | --- |
| `console/server.py` API | 保留并逐步模块化 | 现有接口和 218 项回归已覆盖主要业务 |
| `console/db.py` 与 PostgreSQL | 保留 | 已承担多小说、审核、任务和输出索引 |
| `scripts/` 流水线 | 保留 | 生成和 QA 已验证，重写风险高 |
| `console/static/` | 逐页重构 | 业务行为可复用，但信息架构需要桌面化 |
| Docker Compose | 开发期保留 | 当前可稳定启动后台和数据库 |
| ComfyUI | 保留为可选适配器 | 本地模型仍有价值，但不应成为桌面版前置条件 |

需要新增或替换的部分：

- 新增 Electron 主进程、受限预加载桥接、后台服务管理和启动诊断。
- 将运行配置和数据目录从仓库路径迁移到 Windows 用户数据目录。
- 正式安装包使用托管的 Python 后台与 PostgreSQL 运行时，取消最终用户对 Docker Desktop 的强制依赖。
- 将单页式控制台拆成桌面导航、小说工作区、上下文检查器和任务抽屉。

## 3. 桌面技术路线

选择 Electron 作为桌面容器。

选择依据：

- 当前前端已经以 Chromium 为主要运行环境，可直接复用并保持 Playwright 验收链路。
- 后续需要文件对话框、通知、日志目录、单实例、更新和后台进程管理，Electron 的主进程/预加载模型较成熟。
- 桌面应用本身包含图片预览、漫画页面和本地运行时，安装体积不是当前首要约束。
- 团队可以继续使用现有 HTML/CSS/JavaScript，不需要同时迁移业务 UI 和技术栈。

前端代码采用渐进迁移：既有页面继续运行，新模块使用 Vue 3、Composition API 和 TypeScript；以独立组件为边界逐步替换原生 JavaScript，不进行整页一次性重写。Vite 输出仍由 Python 的 `/static/` 路径提供，因此浏览器模式与 Electron 共用同一套界面资源。

未选择方案：

- Tauri：安装包更小，但当前阶段会同时引入 Rust 命令层、sidecar 打包和 WebView 差异，增加迁移面。
- pywebview：更贴近 Python，但自动更新、受限桥接、窗口生命周期和发行工具链不如 Electron 清晰。

这一选择不是把后台写进 Electron。Electron 只负责窗口、桌面能力和运行时编排；Python/PostgreSQL 仍是业务与数据层。

## 4. 目标运行架构

```text
Comic Pipeline Desktop
  Electron 主进程
    - 单实例、窗口、更新、通知、日志
    - 启动/监控 Python 后台与 PostgreSQL
    - 受限 IPC 白名单
  Electron 渲染进程
    - 桌面工作区 UI
    - 仅访问 loopback API
  Python API/任务进程
    - 现有 console API 与生成任务
  PostgreSQL
    - 小说、章节、设定、素材、审核、任务和输出索引
  Provider adapters
    - 文本 API
    - 图片 API
    - 可选 ComfyUI
```

开发期和发行期分开处理：

| 阶段 | 后台来源 | 数据库来源 | 目的 |
| --- | --- | --- | --- |
| 开发过渡 | 现有 Docker Compose | Docker PostgreSQL | 快速建立桌面壳，不迁移数据 |
| 内部测试 | 打包 Python sidecar | 独立本地 PostgreSQL | 验证无 Docker 启动与数据目录 |
| 正式发行 | 版本化 Python runtime | 桌面托管 PostgreSQL | 安装、升级、备份和恢复 |

## 5. 桌面信息架构

### 全局层

- 首页：最近小说、待处理审核、运行状态、最近任务。
- 项目：小说列表、导入、归档、备份和恢复。
- 审核中心：跨小说审核队列，只负责需要人工决策的项目。
- 任务中心：运行中、失败、可重试任务和日志。
- 设置：模型、生成后端、存储、数据库、桌面行为和更新。

### 小说工作区

```text
小说名称 / 当前阶段 / 总体进度
  项目总览
  原文与章节
  全局设定
  素材库
  章节生产
    拆解与分镜
    漫画生成
    成果审核
```

### 窗口布局

```text
+------------------+-------------------------------------+------------------+
| 232px 自适应侧栏  | 主工作区                            | 共享右侧抽屉      |
| 项目切换          | 页面标题 + 唯一主要操作             | 默认关闭          |
| 全局/项目模块     | 列表、阅读器、素材或漫画画布        | 属性/审核/诊断    |
| 章节生产时切换章节 |                                     | 按需打开          |
+------------------+-------------------------------------+------------------+
| 仅任务运行时显示 32px 进度条；完整队列和日志进入任务中心                  |
+----------------------------------------------------------------------------+
```

布局准则：

- 页面常驻区域只有单一自适应侧栏和主工作区；右侧副信息统一使用共享抽屉。
- 全局导航与小说导航合并进 232px 侧栏，不再使用“64px 图标栏 + 224px 上下文栏”双导航。
- 章节列表只在章节生产时显示在侧栏下半区；标题栏、画布和检查器不再重复章节选择。
- 设定和素材采用“列表/画布 + 右侧编辑器”，两侧独立滚动。
- 章节阅读器一次只展示一个主要任务，原文、拆解、分镜、成片用页签切换。
- 每页只保留一个醒目的主要操作；同一状态不能同时出现在标题、侧栏、正文和底栏。
- 共享抽屉默认关闭且不占宽度；设定准备度、镜头属性、审核详情和任务诊断复用同一容器。
- 抽屉宽 304-320px，使用低对比背景、固定标题和关闭按钮；正文独立滚动，不放章节导航、流程阶段或第二个醒目主操作。
- 抽屉打开后先展示基础信息，模型、质量、种子等放入“高级参数”折叠区。
- 任务日志进入全局任务中心；仅有运行中任务时显示 32px 单行进度条。
- 桌面最小窗口为 1180x720；验收尺寸为 1920x1080、1440x900、1366x768、1180x720。
- `>= 1440px` 时抽屉以停靠方式打开并推动主工作区重排，不遮挡或裁切主内容。
- `1180-1439px` 时抽屉作为临时层覆盖右侧边缘，关闭后立即归还空间；不得转化为常驻右栏。
- 项目总览只保留当前阶段和章节进度；设定准备度进入共享抽屉，不显示最近活动或重复任务流。
- 漫画工作区不常驻阶段条和页面缩略图；阶段放入标题面包屑，页列表按需打开。
- 页面外壳不滚动；侧栏、主工作区和检查器分别管理自己的滚动边界。

### Stitch 设计基线

设计项目：[Comic Pipeline Desktop](https://stitch.withgoogle.com/projects/211301384591597985)

| 设计稿 | Stitch Screen ID | 用途 |
| --- | --- | --- |
| 搜神记 · 项目总览（抽屉关闭） | `d4ebff50746b417e9b9060ce946cc516` | 验证主区全宽、唯一主操作和副信息零占位 |
| 搜神记 · 章节生产（抽屉关闭） | `c49d972eaf154666bb513615487c7ba1` | 验证画布优先、唯一章节列表和运行中任务条 |
| 搜神记 · 章节生产（属性抽屉展开） | `09f5037f1a7f4b0984899226148a5106` | 验证 312px 低权重抽屉、主画布重排和高级参数折叠 |

桌面视觉参考 [BeefTV](https://github.com/glanderness/BeefTV) 的紧凑媒体工作台、低层级深色界面和本地优先交互，但不复制其自由画布结构。漫画流水线继续保留章节顺序、设定确认和人工审核门禁。

统一视觉规则：

- 近黑背景、灰黑工作面和 1px 细边框；蓝色只表示当前步骤和主要操作。
- 青色表示健康或完成，琥珀色表示等待审核，红色表示失败或破坏性操作，状态不能只依赖颜色。
- 标题使用 Manrope，正文使用 Inter；控件高度 32-36px，圆角 4px，面板圆角不超过 8px。
- 不使用渐变、装饰光晕、悬浮章节卡片、嵌套卡片或营销式大标题。
- 界面先做减法：总览不超过三个信息组，工具栏不超过七个操作组，次级操作进入溢出菜单。
- 右侧副信息不得成为常驻栏；所有模块复用同一抽屉，打开新内容时替换当前抽屉。
- 筛选器、分段控件、输入框和按钮共用 36px 对齐基线；图标按钮提供工具提示。
- 漫画画格间距为 4px，图片框内部无留白；内部标识放在画格边界之外，不写入生成图。
- UI 只显示中文业务名称，不显示 `SSJ_COMIC_EP01` 一类内部英文标识。

## 6. 分阶段计划与门槛

### P0 架构与蓝图

交付：本计划、Notion 功能和任务、技术决策、当前界面基线截图。
门槛：后续每个任务都有独立成功标准和验证方式。

### P1 桌面壳

交付：Electron 开发入口、单实例、安全窗口、后台探测/启动、诊断页和日志。
门槛：现有后台运行时能直接进入控制台；后台不可用时不出现空白窗口；重复启动只聚焦现有窗口。

### P1 桌面工作区重构

交付：单一自适应导航、小说工作区、共享右侧抽屉、运行中任务条和逐模块页面。
门槛：全局/项目功能没有重复入口；三个验收尺寸无重叠、遮挡和横向溢出；核心流程可完整操作。

### P1 原生能力

交付：文件选择、打开目录、通知和安全外链。
门槛：`nodeIntegration=false`、`contextIsolation=true`；渲染层不能执行任意命令或读取任意文件。

### P1 数据与运行时

交付：用户数据目录、系统密钥存储、托管 PostgreSQL、备份恢复和 Docker 数据迁移工具。
门槛：迁移前自动备份；失败可回滚；配置和密钥不写入安装目录、仓库、日志或 Notion。

### P2 安装与更新

交付：签名安装包、更新通道、版本信息和回滚。
门槛：干净 Windows 环境安装成功；覆盖升级保留全部用户数据；更新中断可恢复。

### P1 完整验收

交付：桌面 E2E、迁移报告和发行检查单。
门槛：从导入小说到下一章循环通过；断网、模型错误、后台崩溃和重启恢复有明确结果。

## 7. 数据迁移与回滚

现有数据属于用户，任何迁移必须先备份，且不得用“容器健康”代替数据完整性验证。

迁移顺序：

1. 记录当前代码版本、配置来源、数据库版本和项目数量。
2. 导出 PostgreSQL，复制小说、manifests、output 和必要工作流。
3. 校验备份文件大小、哈希和数据库对象数量。
4. 初始化桌面用户数据目录和新数据库。
5. 导入后比较小说、章节、设定、素材、审核、任务和输出数量。
6. 运行只读健康检查和一个可回滚的小样本流程。
7. 保留旧 Docker 数据卷作为回滚来源，直到桌面版本稳定验收。

建议用户数据布局：

```text
%APPDATA%/Comic Pipeline/
  config/
  logs/
  runtime/
  backups/
  updates/

%USERPROFILE%/.comic-pipeline/
  database/

%USERPROFILE%/Documents/Comic Pipeline/
  novels/
  projects/
  output/
```

## 8. 主要风险

| 风险 | 控制方式 |
| --- | --- |
| 桌面壳可运行但仍依赖 Docker | 明确标记开发过渡版；正式发布门槛要求无 Docker 实机验收 |
| Electron 窗口获得过高系统权限 | 安全预加载桥接、IPC 白名单、关闭 Node 集成、拦截外部导航 |
| 关闭窗口中断正在生成的任务 | 后台任务与窗口生命周期解耦；关闭前提示运行中任务状态 |
| 迁移损坏 PostgreSQL 或素材路径 | 备份优先、计数对账、路径重映射、保留旧数据卷 |
| 单页前端继续膨胀 | 以页面和工作区为边界逐步拆分，不在桌面壳任务中做大规模前端重写 |
| 安装体积增加 | 接受 Electron 体积，以稳定桌面能力优先；发行阶段再做依赖裁剪 |
